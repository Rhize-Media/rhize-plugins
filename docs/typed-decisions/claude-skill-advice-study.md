# Claude’s live skill-advice study

This prospective amendment compares ordinary routing with ordinary routing plus a challengeable Laya suggestion. Its unit is a fresh interactive Claude CLI session. One hash of the native session UUID and the versioned study ID assigns the whole session to control or live with equal probability. Resumed conversations without an assignment, background observers, other hosts and headless workers cannot enroll. A named, isolated verification session can exercise the native path outside the analysis population.

The router uses its existing single, deadline-bound Laya call. Both arms get the incumbent suggestion. In the live arm only, an eligible, timely, distinct, shortlisted Laya choice can add a second suggestion. Claude can follow, challenge, choose neither or abstain. A response carries a random private turn token and one reason: fit, wrong choice, missing candidate, wrong question or uncertainty. A challenge may identify the incumbent or an unlisted alternative. Claude can also continue without responding. The study cannot invoke a skill, grant permission, skip checks or change any registry mode.

The SessionStart hook assigns fresh sessions. The router binds the prompt, session, model, ordered options, instrument, policy and emitted payload. The native Stop hook accepts the matching response footer from the current turn. A successful native Skill tool event provides separate usage evidence. A response is neither a label nor proof of invocation or acceptance. Failures and timeouts leave normal routing available. Study evidence lives privately outside the legacy scorer, labels, weekly learning and reserved cohorts. The first response is immutable. Repeated identical feedback is idempotent and a conflict is flagged separately.

## Operation

From the reviewed plugin directory, run `node scripts/skill_study_admin.js start live END_IN_UTC` to freeze the current runtime, skill index, model, registry revision and prospectively chosen end. The default operator directory is `~/.local/share/rhize/skill-advice-study`. Starting refuses an existing config. Run `node scripts/skill_study_admin.js stop` to halt new exposures and retain evidence. The stop is independent of the registry. Pinning or turning off skill-fit, an incompatible source, or expiry prevents new study offers. Only approved, fresh native Claude sessions that load these hooks can participate.

The historical skill-filter comparison retains its frozen router fingerprint. Archive its coverage at cutover as a separate epoch. Do not append live sessions to its shadow comparison. The new trial measures the combined experience of advice and a veto. No new scheduler or automatic promotion is involved.

Run `python3 scripts/skill_study_report.py` to read both arms. It includes every assigned session, eligible and scored turns, native hook deliveries, captured responses, missing responses, observed Skill calls, model latency and unknown usage. The index task is the first eligible request in a session. Independent outcomes distinguish accepted without material rework, completed with material rework, and unsuccessful. Unreviewed tasks and sessions without an index task remain visible. Interruption counts require an independent assessment of the completed task. A native Stop, agreeing with Laya, and a tool invocation establish none of these outcomes.

An independent reviewer may place a private `task-review.json` and its supporting `task-review.evidence` beside the assignment. The packet uses schema `claude-skill-task-review-v1`, the exact session hash, index turn token and prompt hash, basis `explicit_user_review` or `independent_verifier`, result `accepted_without_rework`, `material_rework` or `unsuccessful`, a nonnegative integer `irrelevantInterruptions`, and SHA-256 of the evidence in `evidenceSha256`. Preserve the original evidence, including material corrections. Collect reviews from both arms without showing the reviewer the study arm or response where feasible. Nobody should infer acceptance from silence.

## Decision rule

Report acceptance without material rework by assigned arm, missing-outcome bounds on the difference and independently judged interruptions per completed task. For review require at least 50 independent task outcomes per arm, at least 80% outcome coverage among assigned sessions in each, and no unresolved feedback conflict. These are information floors. They do not establish benefit or authorize expansion. Inspect uncertainty and task mix before interpreting an apparent gain. Keep results inconclusive if the data cannot distinguish the arms. Stop exposure on control leakage, wrong-turn attachment, or changed authority. Repeated wrong-question and missing-candidate reports can nominate future changes for blinded review. Freeze any new question or menu before testing it on subsequent traffic.
